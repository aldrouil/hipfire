## Precedence rules (normative, apply in this order)

R1 — Order of application. Process pages 1 to 4 in order, top to bottom
within each page. Skipped/voided/ignored lines (R2-R4) change nothing and
leave no trace except in the audit counters.

R2 — Duplicates. Any line whose event id has already appeared on any earlier
line is ignored entirely (first occurrence wins), even if the repeated fields
differ (a tampered retransmit is still just a duplicate). Each ignored repeat
increments `audit.ignored_duplicates` by one. A CORRECTION line has its own
fresh event id and is never itself a duplicate unless its own id repeats.

R3 — Corrections. A line `En CORRECTION corrects Em: <replacement>` voids the
original event Em (it is treated as if it never applied) and instead applies
the replacement event at the CORRECTION's own position in the order. Each
voided original increments `audit.voided_originals` by one. If several
CORRECTIONs name the same original, only the LAST one (in page order) takes
effect; each earlier correction for the same target is discarded and
increments `audit.superseded_corrections` by one (it applies nothing). A
CORRECTION naming an unknown event id is ignored and increments
`audit.unknown_corrections_ignored` by one.

R4 — Debit discipline. TRANSFER and FEE debit one account. A debit applied
while its account is FROZEN is rejected (ignored). A debit that would drive
the account balance below zero is rejected (insufficient funds). Every
rejected debit increments `audit.rejected_debits` by one. Credits (incoming
TRANSFER legs) always succeed, even into a FROZEN account. OPENING lines only
set starting balances and cannot be rejected. FREEZE on an already-frozen
account (or UNFREEZE on an active one) is a harmless no-op.

R5 — Fees. Each applied FEE deducts its amount from the named account and
adds the same amount to the FEES sink. The sink is never debited.

R6 — Scope of "largest transfer". `audit.largest_effective_transfer` is the
single successfully APPLIED transfer leg with the greatest amount among
effective (non-voided, non-duplicate) TRANSFER events. Rejected debits,
voided originals, superseded corrections, and unknown corrections are not
candidates. Ties are impossible in this fixture.
